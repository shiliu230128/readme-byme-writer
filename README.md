# product-copy

给 AI 助手装的一套文案本领。你指一个项目或说几句产品情况，它产出面向非技术读者的 GitHub README，或商品售卖页描述。

它跟直接让 AI"写个 README"的区别是：先建事实层再渲染。没有依据的地方不用形容词填，也不在正文里留占位标记。该整段不写就不写，该改成通用做法就改。缺什么信息、补上能修好什么，它在回复里单独告诉你。

## 安装

把这个文件夹复制到 AI 客户端的 skill 目录：

```bash
cp -r ~/Desktop/product-copy ~/.claude/skills/product-copy
```

Claude Code 的目录是 `~/.claude/skills/`；其他客户端见各自文档。

## 怎么用

直接说话，不用记命令：

```
给桌面的 film-curator 写个 README
给这个项目写一份卖货用的详情页文案
两个都要，先售卖页
```

它会先自动读项目里能读的东西，只在真的推不出来时问你几个问题（上限 5 个，一次问完，每个都附带"你不答我按 X 处理"）。

## 你会拿到什么

默认只有正文一个文件。

README 写进项目根目录；目标位置已有 README.md 时不覆盖，写成 `README.draft.md` 让你自己替换。售卖页写到 `~/Desktop/<产品名>-copy/`。

自检结果不写成文件，直接在回复里告诉你哪几条没过、缺什么信息能补好。

想要中间产物就明说"把事实层和自检报告也给我"，它会写到 `.product-copy/` 子目录里：

| 文件 | 是什么 | 什么时候有用 |
|---|---|---|
| `facts.md` | 事实层：能力、边界、前置条件、可预见报错，每条带出处 | 之后还要写落地页、小红书时可复用，不必重新摄取 |
| `ledger.md` | 对账表：卖点-证据-转译、痛点具体度、术语暴露 | 想核对每个卖点凭什么这么说 |
| `review.md` | 完整自检报告 | 想看所有规则的逐条判定 |

## 可以配置什么

在输出目录放一个 `.product-copy/config.json`：

```json
{
  "outputDir": "~/Desktop/copy-drafts",
  "keepIntermediates": true
}
```

`outputDir` 改默认输出位置，`keepIntermediates` 设为 true 则每次都保留中间产物。

指令里直接说"写到 xxx"优先级最高，会盖过配置文件。

## README 的三种模式

同一个项目，README 给谁看决定了怎么写。它会自己判，判错了你直接说。

| 模式 | 什么时候用 | 首屏放什么 |
|---|---|---|
| `交付型` | 私有仓库，或只发给买家 | 怎么装。不写差异化对比，不求 star |
| `公开型` | 免费开源，或用来引流 | 效果图和一句话定位。必须有替代方案对比 |
| `双重` | 公开仓库同时在售卖（默认） | 上半段说服，一个 `## 安装` 之后转交付 |

`双重` 模式有条硬规则：安装小节之上不出现任何命令，之下不出现任何卖点重述。混写会两头都伤，还在观望的人被安装细节赶走，已经付钱的人在宣传话术里找不到第一步。

## 它不会做什么

- 不让你去找素材。README 的报错表从代码里的错误信息字符串抓，前置条件从 CI 配置和 manifest 读。售卖页缺真实痛点时，它会告诉你去客服记录或竞品差评里捞，而不是让你"想几个用户案例"。
- 不默认跑你的项目。只读声明文件和错误字符串就够写出准确的 README。只在声明缺失、且那个信息决定读者会不会卡住时，才跑最小的一条命令（比如 `--version`），并说明为什么要跑。
- 不假设读者懂技术。终端、Python、JSON、环境变量这些词首次出现必须就地解释，命令给 Windows 和 Mac 两套，每段命令上方有一句"这行是干什么的"。
- 不编数字，也不为了"具体"编细节。"用 Excel 记了三次就放弃"这种听着具体但凭空来的说法会被判为幻觉，退回到素材支持的抽象层级。
- 不把缺口写进正文。缺了读者也不卡住的整段不写，缺了会卡住的改成读者能自己解决的通用做法，缺的是价格许可证这类承诺信息就留白等你补，然后在回复里列清单。
- 不把维护者数据当卖点。测试通过数、代码行数、覆盖率对非技术读者是噪音。
- 不把两类文案混着写。README 靠承认边界建立信任，售卖页靠堆证据建立信任，方向相反。所以两个 profile 永不同时加载。

## 目录说明（改规则时看）

```
SKILL.md                          流程与铁律，每次加载，故意写短
references/core.md                素材去哪读 + 事实层模板 + 质量算子 C1–C8 + 五 persona
references/profile-readme.md      README 三模式的规则 P1–P6 / R2–R10
references/profile-salespage.md   售卖页规则 S1–S8
references/humanizer-zh.md        去 AI 痕迹的规则副本，只在你没装 humanizer skill 时才读
references/humanizer-zh.LICENSE.txt  上面那份的 MIT 许可
```

改规则优先改 `core.md` 和两个 profile，别往 `SKILL.md` 加内容。它每次都进上下文，越长模型越容易漏读规则。`humanizer-zh.md` 是外部项目的副本，别改它，你自己的偏好写进 `core.md` 的 C8。

自己领域的高频废词（行业黑话之类）直接追加进 `core.md` 的 C5 禁用词表。

正文写完的最后一步是去 AI 痕迹（C8）。你装了 `humanizer` skill 就调它整篇过一遍；没装也不影响，`references/humanizer-zh.md` 是同一份规则的随包副本，会自动退到那份。
