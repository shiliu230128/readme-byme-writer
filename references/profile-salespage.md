# Profile · 售卖页（营销）

**读者有隐痛或欲望，但还没确认「这是给我的」。默认动作是划走。**

跟 README 反过来：这里信任靠**加法**建立，依据、细节、兜底都要给足，少说等于不够。但加法不是形容词堆叠，也不是把内容排成「三大卖点 + 逐条证据」的对账表，那种整齐本身就让人觉得是模板。依据嵌在叙述里，有一条写一条。

重心在后段。最大的摩擦发生在掏钱那一刻，不是打开那一刻。

结构两大块：**为什么需要它 → 它有什么特色**，然后在读者要掏钱之前把犹豫接住。

---

## 一、为什么需要这个项目

### 1.1 人群与场景认领（第一屏，1-2 句）

参考句式：`如果你 <具体身份或处境>，每次 <具体时刻> 都会 <具体麻烦>，这个就是为你做的`。

**这句话必须能让一部分人主动走开。** 读完觉得「好像谁都适合」就是太泛，重写。卖家本能是卖给所有人，越写越泛，这条规则专门对抗它。

同样过反证测试：换成任意同类产品后仍然成立 → 重写。

### 1.2 痛点与解法（3-5 组）

一组写成：你遇到的情形是什么 → 它怎么处理。

痛点句要含时间、地点、动作或情绪细节，而且换成同品类任意产品后**不能仍然成立**。「收纳不方便」人人点头，无人被戳；「洗完澡伸手拿毛巾，发现钩子挂在门后，够不到」才是痛点。

**但具体度只能来自素材。** 为了具体而编细节，比抽象表述更糟。素材不够时把句子退回抽象层级，别补虚构细节，判定标准见 core.md 的具体度那一节。

每条痛点心里记着出处（客服记录 / 评价 / 用户原话 / 竞品差评 / 推测）。标为推测的超过一半时，在回复里提一句：痛点层缺真实素材，建议去客服记录或竞品差评里捞。不要求用户额外做调研，只指出去哪里捞。

出处是给自检用的，不写进正文。正文里挂一排「来源：客服记录」会显得像审计报告。

### 1.3 带来什么价值

跟替代方案比成本：人工时间、竞品价、自己 DIY 的投入、什么都不做的持续损失。

这里的比较是为了让读者算清账，不是为了贬低竞品。承认某些情况下别的选择更合适，反而提升可信度。

## 二、项目有什么特色

特色不是功能清单。每一条要落在这几种里的至少一种，否则它就只是自夸：解决了前面提过的某个痛点，而且说清怎么解决的；或者是细节上的人性化设计，那种「作者自己用过才会想到」的地方；或者是强于替代方案的地方，用「你不用再做什么」来说，不用参数说。

### 每条特色都要能被核对

写完一条，问一句：这句话凭什么？

答案可以是硬参数、可以是一个具体机制、可以是使用者原话、可以是数量（销量、用户数、star 数）。有就顺手写进句子里，没有就把这条写轻，或者删掉。

常见的失手：

形容词证明形容词。「做工精良，品质卓越」，两句都在等对方提供依据，谁也没提供。

参数直接跳到体验，中间那一环没了。判定和例子见 core.md 的「依据嵌在叙述里」。

为了凑结构而补。三条特色只有两条有依据，第三条就删掉，不要为了「三大特色」的整齐去编。两条讲透比三条注水强。

### 使用者原话不要润色

保留口语。润色成广告语之后就失去了可信度，读者一眼能看出哪句是真人说的，哪句是文案改的。

### 怎么开始用

几步、需要什么条件、多久见效。虚拟产品或服务类要写清交付方式和交付时间。

这一节写简版就好，详细步骤在 README 里。但**售卖页承诺的上手时间必须跟 README 的实际步骤对得上**。承诺三分钟上手而 README 有十一步，要改的是承诺，不是 README。

## 三、掏钱之前

### 3.1 真实的犹豫

FAQ 3-5 条，写读者真正犹豫的问题，不是自问自答式软广。

「问：产品质量好吗？答：我们采用优质材料」这种是在浪费读者的耐心。真实的犹豫长这样：「比同类贵一倍，凭什么？」，然后给出具体差异和可核对的依据。

来源：售前咨询里被问最多的几个问题。没有咨询记录时，用竞品差评里最集中的抱怨反推。

### 3.2 风险兜底

退换、保修、售后承诺，写具体天数和具体条件。虚拟产品写清能不能退、更新管多久。

### 3.3 不适合谁（2-3 条）

大多数售卖页没有这节。它同时降退货率和建信任：敢说不适合谁，说明不是在硬卖。

写不出这一节，说明第一屏的人群还是太泛，回去重写。

### 3.4 行动指令

按载体调整：
- 电商详情页：明确规格选择与下单引导
- 独立落地页：单一明确的 CTA
- 社群短文案：一句行动 + 一个联系入口

## 自检清单

- [ ] 第一屏能让一部分人走开，且过反证测试
- [ ] 每条痛点含时间/地点/动作/情绪细节，换成同类产品后不成立
- [ ] 痛点的出处心里有数，推测占比过半时已在回复里提示；出处没写进正文
- [ ] 每条特色能答出「凭什么」，答不出的已删或写轻
- [ ] 没有形容词互证、没有参数直接跳体验
- [ ] 没有为了凑数而补的特色；也没有把内容排成对账表式的整齐结构
- [ ] 使用者原话保留口语，未润色
- [ ] 承诺的上手时间跟 README 的步骤数对得上
- [ ] FAQ 写的是真实反对意见，不是自问自答
- [ ] 有风险兜底，条件和天数具体
- [ ] 有「不适合谁」
- [ ] 无绝对化违规词（最、第一、国家级、100%、永久）、无医疗功效暗示、无伪造数量词
- [ ] 去 AI 痕迹已真的改写过（优先调 humanizer skill，没装则读 `humanizer-zh.md`）
- [ ] persona ②（犹豫的买家）和 ④（竞品）的问题都答得出
