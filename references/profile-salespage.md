# Profile · 商品售卖页

**读者：有隐痛或欲望、但还没确认"这是给我的"的人。默认动作是划走。**

与 README 相反，这里信任靠**加法**建立：证据、背书、细节、风险兜底。少说等于不够。但加法不等于形容词堆叠，每一条加法都必须是可核验的东西。

重心在**后段**（风险消解与价值锚定）。最大摩擦发生在掏钱那一刻，不是打开那一刻。

## 结构

### 1. 人群/场景认领（第一屏，1-2 句）

强制句式：

```
如果你 <具体身份或处境>，每次 <具体时刻> 都会 <具体麻烦>，这个就是为你做的。
```

- **S1 · 排除测试**：这句话必须能让一部分人主动走开。读完觉得"好像谁都适合" → 太泛，重写。卖家本能是卖给所有人，越写越泛，这条规则专门对抗它。
- **S2**：过 C1 反证测试。

### 2. 主卖点 + 2-3 个支撑点

主卖点必须是**可被感知的结果**，不是参数、不是功能名。

- ❌「采用 XX 技术」
- ✅「插上就用，不用装任何软件」

**S3 · 三列对账**：每个卖点在 core.md 表 1 有对应行，含证据与转译（C3）。无证据的卖点降级为辅助描述或删除，不得留在主卖点位。

### 3. 痛点 → 解法（3-5 组）

```
你遇到的情形：<带时间/地点/动作/情绪的具体瞬间>
它怎么处理：<对应的具体机制>
```

- **S4 · 痛点具体度**：每条痛点句必须含 ≥1 个时间、地点、动作或情绪细节，且替换成同品类任意产品后**不能仍然成立**。填 core.md 表 3 逐条判定。
  - ❌「收纳不方便」：人人点头，无人被戳
  - ✅「洗完澡伸手拿毛巾，发现钩子挂在门后，够不到」
- **S5 · 素材来源标注**：每条痛点标出处（客服记录 / 评价 / 用户原话 / 竞品差评 / **推测**）。标为「推测」的超过总数一半时，在 review.md 提示：痛点层缺真实素材，建议去客服记录或竞品差评捞。**不要求用户额外做调研，只指出去哪里捞。**

### 4. 证据层

每个主卖点至少对应一条：
- 硬参数 / 规格 / 材质 / 工艺
- 资质、检测、认证
- 数量（销量、用户数、使用时长、复购、star 数）
- 使用者原话（保留口语，**不要润色成广告语**，润色后就失去了可信度）

**S6 · 禁止形容词互证**：证据栏出现形容词（"品质卓越""做工精良"）即不合格。

### 5. 怎么用 / 怎么开始

几步、需要什么条件、多久见效。虚拟产品或服务类：写清交付方式与交付时间。

### 6. 风险消解

- 退换 / 保修 / 售后承诺（具体天数、具体条件）
- FAQ 3-5 条

**S7 · 真实反对意见**：FAQ 必须写读者真正犹豫的问题，不是自问自答式软广。
- ❌「问：产品质量好吗？答：我们采用优质材料。」
- ✅「问：比同类贵一倍，凭什么？答：<具体差异 + 可核验依据>」

来源：售前咨询里被问最多的三个问题。没有咨询记录时，用竞品差评里最集中的三个抱怨反推。

### 7. 价值锚定 + 行动指令

锚定 = 与替代方案的成本对比（人工时间、竞品价、自己 DIY、什么都不做的持续损失）。

行动指令按载体调整：
- 电商详情页：明确规格选择与下单引导
- 独立落地页：单一明确 CTA
- 社群短文案：一句行动 + 一个联系入口

### 8. 不适合谁（2-3 条）

大多数售卖页没有这节。它同时降退货率和建信任：敢说不适合谁，说明不是在硬卖。

**S8**：写不出这一节 → 回到第 1 节重写人群，说明定位仍然太泛。

## 长度指引

| 载体 | 篇幅 | 重心 |
|---|---|---|
| 电商详情页 | 长，可分屏 | 证据层 + 风险消解 |
| 独立落地页 | 中 | 痛点→解法 + 单一 CTA |
| 社群短文案 | 200-400 字 | 人群认领 + 一个最强证据 + 行动 |
